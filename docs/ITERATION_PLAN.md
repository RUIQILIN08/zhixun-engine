# 三次迭代方案

每个数据集由平台多轮调用 Harness。每一轮都是一次真实尝试：从当前被选中的
检查点续训、调用一次千问生成计划、提交候选、再用公开验证指标决定更新或回滚。

## 第 1 轮：静态基线确认

- 目标：先让候选沿官方检查点继续训练，确认续训、提交和选择链路正确。
- 假设：在官方初始化状态上小幅续训，能够保持基线水平。
- 行动：使用父检查点继续训练，默认 1 个 epoch，学习率与批大小沿用基线。
- 验收：候选能够提交，平台返回 artifact_id；父与候选的验证指标可比较。

## 第 2 轮：学习率与训练规模调整

- 目标：只改变一个主变量，寻找更稳定的学习率或训练轮数。
- 假设：降低学习率并增加少量 epoch，可以在不剧烈破坏父模型的情况下改善验证指标。
- 行动：由千问在本轮授权范围内提出 epochs、learning_rate、batch_size。
- 验收：候选与父模型在同一验证集上比较，A 看 Macro-F1，B/C 看 RMSE。

## 第 3 轮：漂移适应与冠军挑战者

- 目标：把“发现变差就回滚”固化为自动决策。
- 假设：对新数据继续训练可能有效，也可能过拟合；保留冠军模型最安全。
- 行动：训练挑战者，比较指标；更好则部署，否则回滚父模型。
- 验收：选择结果写入状态，下一轮以被选中的 artifact 为父模型继续。

## 每轮必填字段

- hypothesis：本轮假设；
- change_summary：相对父模型实际改了什么；
- configuration：训练计划、父指标、候选指标、模型调用号；
- reason：为什么选择候选或父模型；
- model_call_ids：本轮真实模型调用号；
- history_ids：本轮实际读取的历史记录 id。
