# 智训引擎：面向工业数据漂移的自主迭代训练系统

## 1. 项目概述

本方案在无 GPU、无公网、4 核 8 GB 内存的 Linux 环境中，构建一个由大模型驱动的
自主训练 Harness。系统读取公开传感器、轴承和发动机数据，在 CPU 上训练轻量工业
模型，并自动完成实验、比较、更新与回滚，以应对工业数据漂移。

## 2. 背景与问题

传感器老化、设备磨损和工况变化会使输入特征、控制项和标签分布逐渐漂移。固定模型
的预测能力会随时间下降。比赛要求系统具备持续发现、诊断、评估和回滚的闭环能力，
而不仅是训练一个模型。

## 3. 总体架构

```text
平台数据
   ↓
Harness：读数据、调模型、提交候选、保存状态
   ↓
大模型：生成本轮训练方案
   ↓
CPU 工业模型：NumPy MLP 训练与预测
   ↓
公开验证集评估
   ↓
更新冠军模型或回滚父模型
```

## 4. 模型方案

工业模型使用官方提供的小型 NumPy MLP：

- A：128 个输入，32 个隐藏单元，6 类 softmax；
- B：34 个输入，24 个隐藏单元，1 个线性 RUL 输出；
- C：24 个输入，32 个隐藏单元，1 个线性 RUL 输出。

所有工业模型参数少于 100,000，无需 GPU。大模型 Qwen/Qwen3.8-27B 仅负责规划和
决策，不直接预测工业标签，也不改写模型权重。

## 5. Harness 与 Agent

系统使用 `contest_harness` 1.0.2 和 `contest.harness.workspace.v2` 协议。每轮流程：

1. 读取父检查点和公开数据；
2. 调用一次千问生成训练计划；
3. 从父检查点继续训练候选模型；
4. 在公开验证集上计算指标；
5. 与父模型比较，决定更新或回滚；
6. 提交候选并结束本轮。

## 6. 基线复现

本地已复现官方开发基线：

| 任务 | 指标 | 结果 |
| --- | --- | --- |
| A | Macro-F1 | 0.7140 |
| B | RMSE | 681.1598 |
| C | RMSE | 52.8686 |

以上为公开验证集的开发参考结果，最终成绩以平台评测为准。

## 7. 漂移应对与回滚

系统采用冠军挑战者机制：候选模型只有在公开验证指标优于父模型时才被采用，否则
保留父模型。状态通过 SDK 的 `state_workspace` 和 `save_state` 保存，下一轮以被
选中的 artifact 作为新的父模型。

## 8. 资源与合规

- 不使用 GPU，不在镜像内保存模型权重或 API Key；
- 只通过 `rnd.model()` 调用平台模型；
- 训练日志写 stderr，stdout 只输出协议 JSONL；
- 数据、模型和代码来源记录在 SOURCE_COMPLIANCE.md。

## 9. 局限与后续

当前第一版默认使用平台基线续训与简单的指标比较。后续可加入漂移检测器、更强的
候选搜索和更细粒度的回滚策略，但必须先通过平台真实评测并保留可复现证据。
